# aihub_doc - Documentation System

**Purpose**: VitePress-based documentation site with automated translation and deployment. Human-readable docs for
platform users and developers.

Tech Stack & Paradigms: VitePress static site generator. vitepress-plugin-mermaid for diagrams. vitepress-plugin-llms
for AI export buttons. Vue 3 framework. Automated EN→DE translation using llm CLI (gemini-2.5-flash model). SHA-256
hash-based change detection for incremental translation. index.en.md files as source of truth, index.de.md
auto-generated. pnpm for package management. Numbered folder structure for sidebar ordering. dayjs for date handling.
cytoscape + cytoscape-cose-bilkent for graph layouts. gray-matter for frontmatter parsing. glob for file finding.
@braintree/sanitize-url for URL safety. Auto-sidebar generation from folder structure. GitHub Pages deployment via
GitHub Actions (.github/workflows/deploy-docs.yml). sync-docs.sh syncs README files from monorepo. translate-docs.sh for
automated translation. Arc42 ADRs in arc42/decisions/ for architectural decisions.

## Scope Responsibility

User-facing documentation with automated English→German translation. NOT for AI agents (use `CLAUDE.md` files) or
internal notes.

## Documentation Workflow

### Writing Documentation

**Source Language**: English (`index.en.md` files) **Translation**: Automatic (German `index.de.md` generated by LLM)

**Rules**:

1. **Only edit `index.en.md` files** - German translations are auto-generated
2. **Keep it concise** - Focus on essential information
3. **Use Markdown** - VitePress-flavored (supports Vue components)
4. **Add frontmatter** - Title, description, order metadata

**Example structure**:

```markdown
---
title: My Feature
description: Brief explanation
---

# My Feature

Content here...
```

### File Naming Convention

- **English (source)**: `index.en.md`
- **German (generated)**: `index.de.md`
- **Never edit**: `index.de.md` files (overwritten on translation)

### Documentation Structure

**Numbered folders** control sidebar order:

- `1_vision_and_positioning/` → First in sidebar
- `2_platform/` → Second in sidebar
- etc.

**Nested structure** creates hierarchy:

```
2_platform/
├── index.en.md              # Platform overview
├── 1_getting_started/
│   └── index.en.md          # Nested page
└── 2_architecture/
    ├── index.en.md          # Architecture overview
    └── 1_core_components/
        └── index.en.md      # Sub-sub page
```

## Translation System

**Automated English→German translation** using LLM.

### How It Works

1. **Detects changes**: SHA-256 hash tracks source file changes
2. **Translates**: Uses `llm` CLI with `gemini-2.5-flash` model
3. **Preserves formatting**: Maintains frontmatter, code blocks, links
4. **Adds metadata**: Embeds `source_sha` in German frontmatter for tracking

### Translation Command

```bash
cd aihub_doc
bash translate-docs.sh
# Or: pnpm run docs:translate
```

**Behavior**:

- ✅ Only translates changed files (SHA comparison)
- ✅ Skips up-to-date translations
- ✅ Shows progress: translated/skipped/failed counts
- ❌ Fails if `llm` CLI not installed (`pipx install llm`)

**Translation prompt**: Defined in `translate-prompt.md`

### Manual Translation Override

If you need to edit German translations manually:

1. **Never recommended** - translations will be overwritten
2. **Alternative**: Edit English source, then re-translate
3. **Emergency**: Edit `index.de.md`, but document why in PR

## Sync System

**Auto-imports README files** from monorepo packages into `docs/6_code_deep_dive/`.

### How It Works

```bash
cd aihub_doc
bash sync-docs.sh
# Or: pnpm run docs:sync
```

**Syncs**:

- Root `README.md` → `docs/6_code_deep_dive/1_introduction/index.en.md`
- `aihub_lib/README.md` → `docs/6_code_deep_dive/aihub_lib/index.en.md`
- `aihub_agent/README.md` → `docs/6_code_deep_dive/aihub_agent/index.en.md`
- etc.

**Exclusions**: Skips nested README files (e.g., `aihub_lib/aihub_lib/auth/README.md`)

**When to sync**: Run before building to include latest README changes.

**Template**:

## Documentation Principles

**Keep it concise**: Focus on essential information, not verbose explanations.

**Code over prose**: Show code examples, not lengthy descriptions.

**Link to code**: Reference actual file paths for ground truth.

**Assume competence**: Target experienced developers, not beginners.

**Update on change**: If code changes, update docs in same PR.
