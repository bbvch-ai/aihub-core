1

Nightly (dev test)

Automatic on push to main

Every merged PR builds a nightly and deploys it for developers.

workflows add-tag.yml → build-*.yml → create-release.yml

2

Code freeze, ship to staging

Manual cut protected branch → Automatic bump main → Merge PR into release → Automatic build + deploy

Cut release/<major>.<minor> to freeze the line. The branch is protected (a ruleset mirroring main): every change lands through a PR that runs the same required checks as main, and force-push and deletion are blocked — no approval is required, merging the PR is the gate. Creating the branch does not build; it only bumps main to the next minor, pushed straight to main via the release deploy key (no bump PR). A candidate ships to staging when a PR is merged into the release line — that runs the staging build and deploys automatically, with no approval gate.

workflows On branch creation: bump-main-target.yml (pushes the bump straight to main). On each PR merge into release/*: build-staging.yml → build-*.yml, create-release.yml.

3

Drop a rejected ticket (revert-out)

Manual revert via PR into release/* → Automatic rebuild

Open a revert PR into the release branch to drop a ticket (the branch is protected, so it goes through a PR, not a direct push). That defers it (it returns next release); to reject it for good, revert on main too, or keep a feature flag off.

workflows build-staging.yml rebuilds on merge. Manual: git revert in a PR into the branch.

4

Promote to latest (atomic)

Manual promote trigger → Automatic gated pipeline

One trigger publishes npm and PyPI, and moves latest only if both succeed. This clean version is what k8s pins.

workflows promote.yml (input: staging tag) → publish-npm.yml + publish-pypi.yml → set-latest.yml

5

Hotfix on a release line

Manual branch + PR → Automatic staging → Manual promote

Fix on the release line and bump the hotfix number, then promote. The PR into the protected release branch runs the same required checks as main (no approval needed); merging it runs the staging build, which deploys with no approval gate. On an older line, latest stays put (backport).

workflows build-staging.yml (on merge) → promote.yml. Manual: PR + bump pyproject patch.

6

Forward-port (cherry-pick to main)

Automatic CI detects the gap → Manual cherry-pick + PR

After a hotfix, CI checks the fix is on main; if not, cherry-pick it so the next release keeps it.

workflows forward-port-check.yml (advisory). Manual: cherry-pick + PR.

7

K8s: customer upgrade (pinned stable)

Manual Helm port + pin → Automatic Helm rollout

Each customer pins a promoted stable version in the aihub-k8s repo and upgrades on request.

workflows none in aihub-core. Manual: ./deploy.sh <slug> (rejects latest/nightly).

!

Important

  • Protected release line, one gate: release/* is protected by a ruleset mirroring main — every change lands through a PR that runs the same required checks, and force-push and deletion are blocked. No approval is required and there is no staging deploy approval: merging the PR is the single gate, and the staging build and deploy then run automatically.
  • Auto bump: cutting release/x.y pushes the next-minor bump straight to main via the release deploy key (a bypass actor on main's ruleset) — no bump PR, no approval, nightly advances immediately. The version is derived from main's pyproject, so a mistyped branch name is skipped by a loud guard; nothing breaks silently.
  • Backport an older line: fix it on its own release/x.y (branch from the tag if it was deleted). Promote sees it is below latest and publishes without moving latest.
  • Drop a ticket: revert via a PR into the release branch and it returns next release; revert on main too, or keep a feature flag off, and it stays out.
  • Migrations: additive and forward-only. Destructive changes wait for a later release (expand, then contract); a feature flag beats a revert.
  • Redeploy an old version: pin aihub_version: vX.Y.Z on the VM (or the version in k8s values). No re-release, latest untouched.
  • Release notes: staging and latest list every PR since the last stable; nightly shows the delta since the previous nightly.
