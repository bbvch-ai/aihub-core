# Environment

Every check in this spike cites this file. **Fill it before running anything** — a result without a pinned environment
is not reproducible, and FerretDB's MongoDB-compatibility surface changes between releases, so the version *is* the
scope of every finding here.

Do not edit this file retroactively to match a later run. If the environment changes, add a new dated section and note
which checks ran against which.

Collected by [`probe_environment.py`](probe_environment.py); verbatim output in
[`logs/00_environment.log`](logs/00_environment.log).

| Target                | —                                               | `localhost:27017`                   |
| Reported `version`    | —                                               | `7.0.77` (the MongoDB version FerretDB emulates) |
| `buildInfo.ferretdb`  | —                                               | `{'version': 'v2.5.0', 'package': 'docker'}` |
| `maxWireVersion`      | —                                               | `21`                                |
| Spike database        | —                                               | `aihub_beanie_spike` (did not exist before this run) |

FerretDB advertises wire version 21 and reports itself as MongoDB 7.0.77. Both matter: a client library gates features
on exactly these, so a Beanie code path may be *selected* on the strength of them and then fail on an operation
FerretDB does not actually implement. Where that happens, record it as the finding — "advertised but unimplemented" is
a different and more dangerous class of problem than an honest rejection.

Databases present at the time of the run:

```
aihub, defaultknowledge, development, emailtesting, followup_affirmation_test,
localknowledge, notreserveddb, retrieval_agent_development, sharedknowledge, test
```

The spike writes **only** to `aihub_beanie_spike`. It must never touch `aihub` (the dev database) or `aihub_test`,
which the test suite drops at session start
(`packages/core/swiss_ai_hub/core/testing/db_isolation.py`).
